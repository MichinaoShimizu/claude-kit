# docs-lazy-load —— 必要な時にだけ必要な文書を読ませる

生成AIエージェントは、セッションの最初に CLAUDE.md や README を読み、
作業の途中で関連する docs/ や `.claude/skills/*/SKILL.md` を読みに行く。
**この「読みに行く」の設計が壊れると、関係ない決め事まで毎回トークンを食う。**

壊れ方は2つしかない。

1. **入口が太る。** CLAUDE.md や README に「その場では要らない詳細」まで
   書いてあると、セッションを開くたびにそれを読むことになる
2. **個々の文書が太る。** 「この話題のときに開く」という区切りがあっても、
   その1文書の中身が際限なく増えると、開いた瞬間の読む量が膨らむ

このスキルは、この2つを**検査で機械に見張らせながら**直す手順。

## 使う前に

`scripts/verify-doc-structure.mjs` をこのリポジトリに置く（このスキル一式を
まるごとコピーしてくれば入っている）。設定は `docs-structure.config.json`
（無ければ既定値。[references/config.md](references/config.md)）。

```bash
node scripts/verify-doc-structure.mjs
```

これは**壊れていることを教えてくれるだけ**で、直すのはこのスキルの仕事。

## 手順

### 1. 入口を軽くする

CLAUDE.md（または README）を開いて、**「常に効いている決め事（MUST）」と
「道案内（どの話題のときにどの文書を開くか）」だけ**が残っているか確かめる。

それ以外 —— 理由・手順の詳細・過去の事例 —— が本文に書いてあったら、
docs ディレクトリ（設定の `docsDir`）に切り出して、入口には1行のポインタ
（表の1行でよい）だけ残す。
**判断基準は「この段落を読まなくても、次に何をすべきかは分かるか」。**
分かるなら詳細は外に出してよい。

### 2. 太った文書を見つける

```bash
node scripts/verify-doc-structure.mjs
```

`[サイズ超過]` が出た文書が対象。**まず中身を見出しで分ける。** よくある切り方:

- **手順の中に「一度きり」と「毎回」が混ざっている** → 一度きりの初期設定を
  別文書に出す（例: `deploy.md` から `deploy-setup.md` を切り出す）
- **1つの見出しの下に複数の独立した話題が並んでいる** → 見出し単位でファイルを分け、
  元の文書からは1〜2行のポインタで指す
- **過去の作業記録・棚卸しの結果が本文に混ざっている** → 別文書（`review-YYYY-MM.md`
  のような一過性の記録用）に出す

分けたら、**元の文書に残った内部リンク（`#見出し`）が、移動した先を指していないか**
必ず確認する。移動先の断片リンクは `他ファイル.md#見出し` の形に直す。

### 3. まだ分割できないなら、TODO に書く

既存の大きいリポジトリに後から入れると、その場で全部は分割できない文書が出る。
**黙って超過させたまま放置しない。** `docs-structure.todo.json`
（既定のファイル名。[references/config.md](references/config.md)）に
理由つきで書く。

```json
[
  { "path": "docs/deploy.md", "reason": "初期設定と独自ドメインの節がまだ混ざっている" }
]
```

これで検査は落ちなくなるが、**`node scripts/verify-doc-structure.mjs` を
走らせるたびに一覧に出る。** 見なかったことにできない状態を作るのが狙い。
直したら **エントリを消すこと。** 消し忘れると `[TODO の掃除]` で検査が落ちる
（直したのに借金が残ったふりをしている状態を許さない）。

### 4. CI に差し込む

push・PR の前に必ず通るようにする。差し込み方は [README.md](../../../README.md) の
「CI に足す」を見る。**ローカルで手元に置くだけでは、直後にまた太る。**

### 5. 維持する

一度直しても、書き足すたびにまた太る。**新しい文書を足す回・既存の文書に
書き足す回のたびに `node scripts/verify-doc-structure.mjs` を通す**のを
push 前検証の一部に入れておけば、崩れた瞬間に機械が教えてくれる。

## 対象にしないこと

- **文章の質や正確さは見ない。** 見ているのは構造（参照・孤立・サイズ）だけ
- **何を書くべきかは判断しない。** 「この決め事は MUST か、道案内で十分か」の
  判断は人か、そのリポジトリの原則に照らして行う
