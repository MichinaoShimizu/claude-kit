# 設定ファイルの中身

`.claude/skills/docs-lazy-load/SKILL.md` から来る。検査スクリプトの設定を
変えたいとき・TODO ファイルの書き方を確かめたいときに読む。

## `docs-structure.config.json`

リポジトリ直下に置く。無ければ全部既定値で動く。

```json
{
  "entryPoints": ["README.md", "CLAUDE.md"],
  "docsDir": "docs",
  "skillsDir": ".claude/skills",
  "pathRoots": ["src/", "docs/", "scripts/", ".claude/", ".github/"],
  "maxDocBytes": 30000,
  "todoFile": "docs-structure.todo.json"
}
```

| キー          | 意味                                                                 |
| ------------- | -------------------------------------------------------------------- |
| `entryPoints` | 索引になる文書。他から参照されていなくてよい起点                     |
| `docsDir`     | 話題ごとの詳細文書を置くディレクトリ                                 |
| `skillsDir`   | スキル定義を置くディレクトリ（`<skillsDir>/<name>/SKILL.md` を想定） |
| `pathRoots`   | 本文中のバッククォートをパスとして検査する接頭辞                     |
| `maxDocBytes` | 1 文書の上限（バイト数）。超えたら分割するか TODO に書く             |
| `todoFile`    | 例外リストの置き場所                                                 |

`maxDocBytes` の決め方: いきなり厳しくしない。まず上限なしで検査を走らせて、
いまある文書の中で一番大きい「これはこのままでよい」と思えるものより
1〜2 割大きい値から始める。厳しくしすぎると、正当な理由がある文書まで
無理に分割することになる。

## `docs-structure.todo.json`

**上限を超えているが、いま分割できない文書の申告リスト。** 超過を検査に
見逃させるのではなく、超過を認めたうえで「わかっていて残している」ことを
毎回の実行結果に出し続けるための仕組み。

```json
[
  { "path": "docs/deploy.md", "reason": "初期設定と独自ドメインの節がまだ混ざっている" }
]
```

- **`path` はリポジトリ直下からの相対パス。** 検査対象の文書一覧に無いパスを
  書くと「この文書がもう無い」で検査が落ちる（掃除し忘れを検知する）
- **`reason` は必須ではないが書く。** あとで見た人（未来の自分を含む）が
  「なぜ残っているか」を追えるようにする
- **直したら消す。** 上限内に収まった文書がまだ載っていると、
  「もう上限内に収まっている」で検査が落ちる

新規に導入するリポジトリで、既存の文書がまとめて上限を超えているときは、
**その時点の全件をここに書いてから運用を始めてよい。** 以後は新しく書く文書・
書き足す文書から上限を守り、TODO のリストは減らす方向にだけ動かす。
