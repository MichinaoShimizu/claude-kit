# 重複検査の細目

[SKILL.md「3. 重複特定」](../SKILL.md#3-重複特定)・[config.md](config.md)から
参照される。準一致重複の有効化方法・意図した重複の許可方法を確認する際に
参照する。

## 準一致重複（`checkNearDuplicates`）

完全一致では、CommonMark ASTから抽出した段落本文を比較する。強調など本文を
変えない書式差は無視し、リンク先・リンクタイトル・コードスパンの内容は区別する。
`minDuplicateChars` はこの本文の文字数に適用する。

完全一致の重複検査では、句読点や敬体/常体（です・ます調 / だ・である調）
だけが違う段落を検出できない。`checkNearDuplicates` を `true` にすると、
句読点の全角/半角・代表的な敬体語尾（「です」「ます」「ございます」など）
を正規化して再比較する（意味的な類似判定ではなく定型文字列の置換のみ）。
完全一致で検出済みの組は二重に報告しない。

既定で無効なのは、判定基準を緩めると誤検知が増えるため。有効化して
誤検知が多ければ `minDuplicateChars` を上げるか、意図した表記差には
`<!-- verify-docs:allow-duplicate -->` を使用する（「意図した重複を
許可する」参照）。

## 意図した重複の許可

免責文言・定型の注意書きなど、意図的に複数文書へ同一段落を配置したい場合が
ある。該当段落の直前の非空行に、単独行として以下を配置する。コメントと段落の
間には空行を挟んでもよい。

```markdown
<!-- verify-docs:allow-duplicate -->
この段落はこども向けページと大人向けページの両方に意図して重複させている。
```

マーカーの後に続く最初の段落のみが重複検査から除外される（サイズ超過の TODO と
異なりファイルに痕跡は残らない）。段落の近傍に理由を記載できるため、
コメントで「なぜ重複させているか」も併記することを推奨する。
