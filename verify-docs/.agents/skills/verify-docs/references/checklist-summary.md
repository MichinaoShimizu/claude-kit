# 完了時の総評記載

[checklist.md](checklist.md) の全項目にチェックが入ったら、実行したスキルの
セクション末尾に `### 総評` を作る。総評は、作業の説明文ではなく「何を確認し、
何が変わり、何が残ったか」を短く再確認できる完了レコードとする。

`node scripts/verify-docs.mjs --json` の `summary` を基準に、次の固定構造で記載する。
全項目を埋める。該当がない値は `なし` または `0件` と明記し、空の見出しや表は
残さない。

```markdown
### 総評

| 項目 | 結果 |
| --- | --- |
| 検査範囲 | 3文書 / 見出し12件 / 段落34件 / 17,799B |
| 検出・是正 | 重複2件を統合、リンク切れ0件、最終検査は違反0件 |
| 作業時間 | 12:40〜12:42（2分24秒） |
| TODO | なし |

#### 変更

| 対象 | 操作 | サイズ変化 | 根拠 |
| --- | --- | ---: | --- |
| `verify-docs/SKILL.md > 導入` | 手順を参照文書へ移動 | 11,549B → 11,269B (-280B) | 12〜35行目 |
| `dedupe-docs/SKILL.md` | 重複説明を統合 | 9,932B → 6,530B (-3,402B) | 文書全体 |

#### 残件・注記

- 常時読み込みからオンデマンドへ移動: 3,881B
- 分割候補: `docs/deploy.md > 独自ドメイン`（42〜118行、4,812B）
```

## 記入規則

- **検査範囲**は `summary.documents` の `count`・`headings`・`paragraphs`・`bytes` を
  使用する。dedupe-docs / tighten-docs だけを実行した場合は、その対象範囲を併記する
- **検出・是正**は `summary.violations.byKind` の開始時点の件数と、実施した是正を
  まとめる。最終検査の違反件数を必ず書く
- **作業時間**はチェックリスト作成時刻から総評記録時刻までとする。git管理下では
  作業前後のコミット時刻で代用してよい
- **TODO**は `summary.todo.entries` を要約する。存在するときは対象節も記す
- **変更**は実際に変更した対象だけを行として記録する。サイズ不変のときは
  `変更なし` と書き、表全体を省略してよい
- **根拠**には違反出力の `location.headingPath` と行範囲を使う。文書全体を変更した
  場合だけ `文書全体` とする
- **残件・注記**には、オンデマンド化した量、`summary.largestSections` のうち次回の
  分割候補として意味があるもの、判断上の例外だけを書く。なければ `なし` とする

サイズ変化率を併記する場合は `(1 - 変更後 / 変更前) * 100` を小数第1位までで計算する。
親見出しと子見出しの `bytes` は重複するため、節サイズを合算しない。
