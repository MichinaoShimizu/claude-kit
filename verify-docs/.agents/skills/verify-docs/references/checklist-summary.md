# 実行結果と完了レコード

[checklist.md](checklist.md) は、各スキルの作業記録と、3スキルを連続実行した回の
全体記録を分ける。単独で完了したスキルは自分のセクションに `### 実行結果` を残す。
verify-docs・dedupe-docs・tighten-docs が同じ回にすべて完了した場合だけ、
`## 完了レコード` を更新する。個別の実行結果で全体集計を繰り返さない。

## 各スキルの実行結果

各スキルのセクション末尾に、次の形式で記載する。対象・実施内容・最終検査・
判断保留のみを残す。文書総数、TODO、全体サイズ、大きい節はここに書かない。

```markdown
### 実行結果

| 項目 | 結果 |
| --- | --- |
| 対象 | `docs/deploy.md > 独自ドメイン`（42〜118行） |
| 実施 | 重複した初期設定の説明を統合し、元の位置をポインタ化 |
| 最終検査 | `node scripts/verify-docs.mjs` — 違反0件 |
| 判断保留 | なし |
```

## 連続実行の完了レコード

3スキルすべてが同じ回に完了した場合だけ、`node scripts/verify-docs.mjs --json` の
`summary` を基準に `## 完了レコード` を更新する。これは「何を確認し、何が変わり、
何が残ったか」を短く再確認できる唯一の全体サマリーである。全項目を埋める。該当が
ない値は `なし` または `0件` と明記し、空の見出しや表は残さない。

```markdown
## 完了レコード

更新: 2026-09-13T14:20:00+0900

| 項目 | 結果 |
| --- | --- |
| 検査範囲 | 3文書 / 見出し12件 / 段落34件 / 17,799B |
| 検出・是正 | 重複2件を統合、リンク切れ0件、最終検査は違反0件 |
| 作業時間 | 12:40〜12:42（2分24秒） |
| TODO | なし |

#### 変更

| 対象 | 操作 | サイズ変化 | 根拠 |
| --- | --- | ---: | --- |
| `verify-docs/SKILL.md > 導入` | 手順を参照文書へ移動 | 11,549B → 11,269B (-280B) | 12〜35行目 |
| `dedupe-docs/SKILL.md` | 重複説明を統合 | 9,932B → 6,530B (-3,402B) | 文書全体 |

#### 残件・注記

- 常時読み込みからオンデマンドへ移動: 3,881B
- 分割候補: `docs/deploy.md > 独自ドメイン`（42〜118行、4,812B）
```

## 記入規則

- **実行結果**は、そのスキルの作業だけを記す。`最終検査` は実行したコマンドと
  成否を記し、判断保留がある場合は人への報告先または保留理由を記す
- **検査範囲**は `summary.documents` の `count`・`headings`・`paragraphs`・`bytes` を
  使用する。これは完了レコードだけに記す
- **検出・是正**は `summary.violations.byKind` の開始時点の件数と、実施した是正を
  まとめる。最終検査の違反件数を必ず書く
- **作業時間**はチェックリスト作成時刻から完了レコード更新時刻までとする。git管理下では
  作業前後のコミット時刻で代用してよい
- **TODO**は `summary.todo.entries` を要約する。存在するときは対象節も記す
- **変更**は実際に変更した対象だけを行として記録する。サイズ不変のときは
  `変更なし` と書き、表全体を省略してよい
- **根拠**には違反出力の `location.headingPath` と行範囲を使う。文書全体を変更した
  場合だけ `文書全体` とする
- **残件・注記**には、オンデマンド化した量、`summary.largestSections` のうち次回の
  分割候補として意味があるもの、判断上の例外だけを書く。なければ `なし` とする

サイズ変化率を併記する場合は `(1 - 変更後 / 変更前) * 100` を小数第1位までで計算する。
親見出しと子見出しの `bytes` は重複するため、節サイズを合算しない。
