# tighten-docs —— 意味を変えない文書簡潔化

verify-docs の検査はサイズ超過という結果のみを見る。冗長かどうかの判定・
削り方は検査対象外であり、本スキルが人・エージェントの判断で埋める。

## 前提

対象リポジトリに verify-docs 一式（`scripts/verify-docs.mjs` と
`.claude/skills/verify-docs/`）が導入済みであること。検査対象・チェックリスト
規約は流用する。verify-docs 自体の規約は
[verify-docs/SKILL.md](../verify-docs/SKILL.md) を参照する。

## 守ること

意味は変えない。数値・条件・手順の順序・免責文言は一字一句変更しない。
判断基準は「削っても次に何をすべきか・何が言いたいかが変わらないか」。
構造の是正（分割・重複解消）は
[verify-docs スキル](../verify-docs/SKILL.md)・
[dedupe-docs スキル](../dedupe-docs/SKILL.md)の担当であり、本スキルの
対象外。同じ変更に混在させず別コミットにする。

## 手順

### 1. チェックリスト作成

作り方は
[verify-docs/references/checklist.md](../verify-docs/references/checklist.md)
を参照する。

### 2. 冗長表現削減

典型パターン。

- **見出し直後の言い換え文**: 見出しをそのまま言い換えているだけで情報を
  追加していない一文が、見出し直後に置かれている状態
- **体言止め**: 見出しが「〜する」で終わる動詞句のままになっている状態。
  可能な限り名詞句に言い換える。省略できる助詞（の・を等）は省略して
  複合名詞にする（例:「重複を削る」→「重複削減」、「サイズの変化」→
  「サイズ変化」）
- **同一理由の重複説明**: 同じ理由を複数回言い換えて説明している状態
- **強調の重ね置き**: 強調のための太字・繰り返しが、説明の直後にも
  重ねて置かれている状態
- **冗長接続表現**: 無くても意味が通じる接続表現（例:「〜だからである」）
- **枕詞**: 削っても文意が変わらない前置き（例:「なお、」「ちなみに」
  「基本的には」）
- **冗長な可能表現**: 回りくどい可能表現
  （例:「〜することができる」→「〜できる」）
- **形式名詞の多用**: 「〜という」を挟むだけで名詞化している表現
  （例:「〜するということ」→対応する名詞句）
- **不要な受け身**: 主語が明確なのに使われている受け身表現
  （例:「〜が行われる」→「〜する」）
- **冗長な条件節**: 分岐が実質1つしかないのに毎回明示している条件節
  （例:「〜の場合には」）
- **重複例示**: 同じ論点を示す例示が複数列挙されていて1つで足りる状態
- **「〜を行う」表現**: サ変名詞に「〜を行う」を続けているだけの表現
  （例:「テストを行う」→「テストする」）
- **同義語の重ね書き**: 漢語と和語で同じ意味の動詞を並べているだけの
  表現（同義語2語を「・」で並べる形。重言との違いは後述）
  （例:「検討・考慮する」→「検討する」）
- **括弧内言い換え注釈**: 括弧内の注釈が本文の単純な言い換えで、本文
  だけで意味が通じる状態（例:「〜秒（つまり〜秒間）」→「〜秒」）
- **話題化マーカー**: 外しても文意が変わらない話題化の表現
  （例:「〜については、」）
- **二重否定**: 意味を変えずに肯定形へ言い換えられる否定の否定
  （例:「〜ないわけではない」→「〜である」）
- **語句の連続誤字**: 誤字起因で同一語句が連続しているだけの箇所
  （例:「〜のの」「〜するする」）
- **概数の二重化**: 概数表現を二重に示しているだけの箇所
  （例:「約100個程度」→「約100個」）
- **重言**: 一方の語がもう一方の意味を既に含んでいるのに両方を続けて
  使っている複合表現（上記「同義語の重ね書き」は同義語2語を「・」で
  並べる形だが、重言は1つの複合語の中に意味の重複が埋め込まれている
  点で異なる）。例:「まず最初に」→「まず」、「後で後悔する」→
  「後悔する」、「今の現状」→「現状」、「従来から」→「従来」、
  「頭痛が痛い」→「頭痛がする」、「違和感を感じる」→「違和感がある」、
  「馬から落馬する」→「落馬する」
- **連続空行の冗長化**: 2行以上連続する空行。Markdown上は1行の空行と
  同じ意味になる
- **強調記法の二重掛け**: 太字と斜体を同じ語句に重ねて使っている箇所。
  片方の記法だけで強調は伝わる（例: `**_強調_**` → `**強調**`）
- **リンクテキストのURL再掲**: リンクテキストがURL文字列そのものの
  繰り返しになっている箇所（例: `[https://example.com](https://example.com)`
  → `<https://example.com>`）
- **表形式の記号オーバーヘッド**: 各行が単純な対応関係（用語→定義の
  ような1対1）に過ぎないのに表（ヘッダー区切り行・各行の`|`）を
  使っている箇所。箇条書き（`- **用語**: 定義`）で同じ対応関係を、
  区切り記号を増やさずに表現できる
- **装飾目的の絵文字**: 見出し・箇条書きの先頭にある、削っても構造や
  意味の認識に影響しない絵文字（例:「## 🚀 デプロイ手順」→
  「## デプロイ手順」）

### 3. サイズ変化記録

[checklist.md「サイズ変更時の記録」](../verify-docs/references/checklist.md#サイズ変更時の記録)
の様式（圧縮前後サイズ・圧縮率）に従う。

### 4. 是正後再検査

```bash
node scripts/verify-docs.mjs
```

書き換えに伴うリンク切れ・断片リンク切れが発生していないか確認する。

## 完了条件

以下を全て満たした時点で完了とする。

- チェックリストの全項目にチェックが入っている
- `node scripts/verify-docs.mjs` が「文書構造: すべて通過」で終わっている
- 作業完了を報告する際は、チェックリストファイルのパスと総評
  （[verify-docs/references/checklist-summary.md](../verify-docs/references/checklist-summary.md)
  参照）を人に伝える

## 対象外とする範囲

- **文章の巧拙・語彙選択の良し悪しの評価。** 主観的な判断には踏み込まず、
  「意味を変えずに削れるか」のみを判断する
- **構造の是正（分割・重複解消）。** verify-docs・dedupe-docs スキルの担当
- **意味を変える書き換え。** 要約・言い換えで内容が変わるものは
  verify-docs の「守ること」に反する
