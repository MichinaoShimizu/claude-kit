# 作業チェックリストの作り方

[verify-docs スキル](../SKILL.md)・[dedupe-docs スキル](../../dedupe-docs/SKILL.md)
の両方から参照される。verify-docs 側に置くのは、dedupe-docs が任意導入
（[verify-docs/README.md「導入」](../../../../README.md#導入)参照）なのに対し、
verify-docs 自体は検査実行前に必ずこの手順を要求するため（依存の向きを
逆にしない）。意味的重複の探索・機械チェックの是正のいずれを始める前にも、
本ファイルの手順でチェックリストを先に作る。

## 必ず物理ファイルとして作る

**作業開始時に、対象文書の一覧（または違反一覧）を単一のチェックリストと
してリポジトリ直下の `.verify-docs/dist/` 配下に物理ファイルとして作る。
この作成を省略してはならない**（「今回は簡単な確認だから」「1件だけ
だから」「実行環境のタスク管理機能を使ったから」は理由にならない——
タスク管理機能は記録が作業者の裁量に依存し省略や消失に気づけないため、
正本にはしない）。

作業に取りかかる前に、まず以下を実行してディレクトリを作り（無ければ
作られる。既にあれば何もしない）、チェックリストファイルを作成する。

```bash
mkdir -p .verify-docs/dist
cat > .verify-docs/dist/$(date +%Y-%m-%dT%H%M%S%z).md <<EOF
# verify-docs-checklist: $(date +%Y-%m-%dT%H:%M:%S%z)

- [ ] 文書パス1
- [ ] 文書パス2
EOF
```

ファイル名・タイトル行の日時はどちらも `date` コマンドがその場で埋める
（開始時刻の記録を兼ねる）。ファイル名に作業内容の識別子は含めない
（同時に複数の作業を始めない限り日時だけで一意になり、命名に悩む
手間を無くす）。チェックボックスの中身は実際の対象に置き換える。
実行環境のタスク管理機能（`TaskCreate`/`TaskUpdate`
など）が使える場合は、進捗の可視化のために**併用してもよいが物理
ファイルの代わりにはできない**。**手段を問わず、置き場所は1つに保つ**
（会話中の複数メッセージに分けて書く、同じ作業のリストを複数ファイルに
分散させる、といったことはしない）。`.verify-docs/` は
[config.md「作業チェックリストの保管先」](config.md#作業チェックリストの保管先verify-docs)
の通り検査対象から除外されるため、**作業ログとして削除せず残してよい**。

## リストの運用

**リストの並び順は、確認する順番をそのまま表す。** 項目の並び替え・削除は
行わない——確認済みの項目もチェックを付けたまま残し、消さない。これにより
リストを見るだけで「何を・どの順で確認する予定か」と「どこまで終わったか」
の両方が常に分かる状態を保つ。

1件確認し終えるたびに、その項目にチェックを入れ（`- [ ]` → `- [x]`）、
**日付・判断理由を書き添える**（`verify-docs.todo.json` の `reason` 欄・
`allow-duplicate` マーカーの理由コメントと同じ考え方）。実行環境のタスク
管理機能を併用する場合も、判断理由（例:「重複なし」「X に統合しポインタ化」
「要人確認」）は物理ファイル側に明記する。

記入例（3件中2件を確認済み、1件は未確認のまま次に控えている状態）:

```markdown
- [x] README.md — 2026-09-12 / 重複なし
- [x] CONTRIBUTING.md — 2026-09-12 / SKILL.md と重複 → ポインタ化して統合
- [ ] verify-docs/README.md
```

**この手順の判定は再現性を持たない（同じ入力でも見落としが起こりうる）。**
その見落としの一種である「確認したつもりで確認し忘れた項目」・
「チェックリストを作らずに検査だけ実行してしまう」の両方を機械的に
防ぐのがチェックリストの役目である。全項目にチェックが入るまで次の
判断段階には進まない。

### サイズを変更した場合の記録

分割・統合・ポインタ化によって文書のバイト数を変えた項目は、**圧縮前
サイズ・圧縮後サイズ・圧縮率を該当項目に記載する。** 圧縮率は
`(1 - 圧縮後 / 圧縮前) * 100` で計算し、小数第1位までとする。

```markdown
- [x] verify-docs/SKILL.md — 2026-09-12 / チェックリスト作成手順を
      references/checklist.md へ切り出し / 11,549B → 11,269B（2.4%減）
```

## 完了時に総評を書く

全項目にチェックが入った時点で、チェックリストファイルの末尾に総評を
記載する（省略不可）。記載項目・テーブル様式・記入例は
[checklist-summary.md](checklist-summary.md) を参照する（本ファイルでは
再掲しない）。
