# verify-docs —— 必要な時にだけ必要な文書を読ませる

生成AIエージェントは、セッション開始時に CLAUDE.md・AGENTS.md・README を読み、
作業途中で関連する docs や `.claude/skills/*/SKILL.md` を参照しに行く。
**この設計が破綻すると、関係ない決め事まで毎回トークンを消費する。**

破綻のパターンは3種類ある。

1. **入口が肥大化する。** CLAUDE.md・AGENTS.md・README に「その場では不要な
   詳細」まで記載されていると、セッションを開くたびにそれを読むことになる
2. **個々の文書が肥大化する。** 「この話題のときに開く」という区切りが
   あっても、その1文書の中身が際限なく増えると、開いた瞬間の読む量が
   膨張する
3. **同一説明が複数文書に重複する。** コピー後に片方のみ更新すると、
   矛盾した2つの説明が残留する。文書分割時にも発生しやすい

## 守ること

**分割・重複解消は「移動」と「ポインタ化」のみで行う。要約・言い換え・
簡略化による内容変更を禁止する。** 本スキルが是正するのは構造（記載場所）
であり、内容（記載事項）ではない。特に数値・条件・手順の順序・免責文言は
一字一句変更しない。「ついでに読みやすく整える」を混在させると、意味の
変化に誰も気づけないまま分割のみが完了した状態になる。

内容そのものの見直し（陳腐化・冗長・不明瞭）が目的であれば、それは
本スキルの対象外であり、別作業（内容のレビュー・書き直し）として分離して
実施する。1つの変更に「構造の是正」と「内容の是正」を混在させると、
どちらの変更で意味が変わったかを追跡できなくなる。

## チェッカーとプレイブックを分離する

本スキル一式は2つに分かれている。**同一の回で両方を兼務させない**
（審査対象と審査基準が同一の判断軸を持つと、審査精度が低下する）。

- **チェッカー**（`scripts/verify-docs.mjs`）—— 機械的に判定できる事項のみを
  検査する。参照切れ・孤立・サイズ超過・完全一致の重複。**「これは MUST に
  値するか」「文章として自然か」といった判断は行わない**
- **プレイブック**（本ファイル）—— チェッカーが検出した事項を、人・
  エージェントがどう是正するかの手順。チェッカーでは検出できない判断を
  要する事項（意味的な重複の判定など）は、必要に応じて別スキルに切り出す
  （例: [dedupe-docs スキル](../dedupe-docs/SKILL.md)）

## 使用前提

`scripts/verify-docs.mjs` を対象リポジトリに配置する（本スキル一式を
まるごとコピーすれば含まれる）。設定は `verify-docs.config.json`
（無ければ既定値。[references/config.md](references/config.md)を参照）。

```bash
node scripts/verify-docs.mjs
```

本スクリプトは**破綻箇所を通知するのみ**であり、是正は本スキルの役目である。

## 手順

### 1. 入口を軽量化する

CLAUDE.md・AGENTS.md（または README）を開き、**「常に効いている決め事
（MUST）」と「道案内（どの話題のときにどの文書を開くか）」のみ**が残って
いるかを確認する。**この2つの入口ファイルはルーティングテーブルに徹する**
—— 話題と行き先の対応表であり、理由・手順を記載する場所ではない。

それ以外 —— 理由・手順の詳細・過去の経緯 —— が本文に記載されていれば、
docs ディレクトリ（設定の `docsDir`）に切り出し、入口には1行のポインタ
（表の1行で足りる）のみを残す。**判断基準は「この段落を読まなくても、
次に何をすべきかが分かるか」。** 分かる場合、詳細は外部に切り出してよい。

**「簡潔に削れるか」も同様で、冗長な言い回しの削減・圧縮の是非は、
執筆者本人または原則審査の役目である。** チェッカーが検査するのはサイズと
いう結果のみであり、削り方自体は検査対象外である。

### 2. 肥大化した文書を特定する

```bash
node scripts/verify-docs.mjs
```

`[サイズ超過]` が出力された文書が対象となる。**まず見出し単位で内容を
仕分ける。** 典型的な切り分け方は以下の通り。

- **手順の中に「一度きり」と「毎回」が混在している** → 一度きりの初期設定を
  別文書に切り出す（例: `deploy.md` から `deploy-setup.md` を切り出す）
- **1つの見出しの下に複数の独立した話題が並んでいる** → 見出し単位でファイルを
  分割し、元の文書からは1〜2行のポインタで参照する
- **過去の作業記録・棚卸し結果が本文に混在している** → 別文書（`review-YYYY-MM.md`
  のような一過性の記録用）に切り出す

分割後は、**元の文書に残った内部リンク（`#見出し`）が、移動先を指していないか**
必ず確認する。移動先の断片リンクは `他ファイル.md#見出し` の形式に修正する。
**分割は重複を生みやすい作業でもある。** 同一段落を両方に残していないか、
分割後に再度検査を実行する（次の「3.」を参照）。

### 3. 重複を特定する

`[重複]` が出力された場合、同一内容が複数文書にそのまま存在している。

- **どちらを本来の置き場所とするかを決定する。** 話題として詳細な側・
  上位の文書（README よりは docs）に残し、他方はポインタ1行に置換する
- **両者が独立に存在すべき理由がある場合**（例: 免責文言を子ども向け・
  大人向けの両方に配置する必要がある場合）、重複させたい段落の直前に
  `<!-- verify-docs:allow-duplicate -->` を配置して検査対象から除外する。
  **これは「見なかったことにする」処置ではなく「意図した重複であることを
  宣言する」処置**であり、乱用しないこと
- `[準一致重複]` は既定で無効な `checkNearDuplicates` を有効化した場合のみ
  出力される。句読点・敬体/常体の差異のみを吸収した重複であり、是正方法は
  `[重複]` と同一（詳細は [references/config.md](references/config.md) の
  「準一致重複」を参照）

#### 意味的な重複（チェッカーでは検出できない）

`[重複]`・`[準一致重複]` はいずれも文字列一致ベースであり、言い回しが
異なる言い換えの重複は検知できない。この判断は
[dedupe-docs スキル](../dedupe-docs/SKILL.md) を参照する。

### 4. 分割できない場合は TODO に記載する

既存の大規模リポジトリへの後発導入では、その場では分割できない文書が
発生する。**超過を黙認して放置しないこと。** `verify-docs.todo.json`
（既定のファイル名。[references/config.md](references/config.md)を参照）に
理由を付して記載する。

```json
[
  { "path": "docs/deploy.md", "reason": "初期設定と独自ドメインの節がまだ混ざっている" }
]
```

これにより検査は通過するが、**`node scripts/verify-docs.mjs` を実行する
たびに一覧に出力される。** 見なかったことにできない状態を維持することが
目的である。是正後は**エントリを削除すること。** 削除漏れは
`[TODO の掃除]` により検査失敗となる（是正済みにもかかわらず負債が
残存しているふりを許容しない）。

### 5. CI に組み込む

push・PR の前に必ず通過するよう構成する。組み込み方法は [README.md](../../../README.md)
の「CI への組み込み」を参照する。**ローカルに配置するのみでは、直後に
再度肥大化する。**

### 6. 維持する

一度是正しても、追記のたびに再度肥大化・再度重複が発生する。**新規文書
追加時・既存文書への追記時に毎回 `node scripts/verify-docs.mjs` を実行する**
ことを push 前検証の一部に組み込めば、崩れた時点で機械的に検知できる。

## 対象外とする範囲

- **文章の品質・正確性は検査対象外とする。** 検査対象は構造（参照・孤立・
  サイズ・重複）のみである
- **何を記載すべきかの判断は行わない。** 「この決め事は MUST か、道案内で
  足りるか」「どちらの表現が簡潔か」の判断は、人または対象リポジトリの
  原則に照らして行う
