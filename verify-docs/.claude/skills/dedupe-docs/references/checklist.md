# 作業チェックリストの作り方

[dedupe-docs スキル](../SKILL.md)・[verify-docs スキル](../../verify-docs/SKILL.md)
の両方から参照される。意味的重複の探索・機械チェックの是正のいずれを
始める前にも、本ファイルの手順でチェックリストを先に作る。

## 必ず物理ファイルとして作る

**作業開始時に、対象文書の一覧（または違反一覧）を単一のチェックリストと
してリポジトリ直下の `.verify-docs/dist/` 配下に物理ファイルとして作る。
この作成を省略してはならない**（「今回は簡単な確認だから」「1件だけ
だから」「実行環境のタスク管理機能を使ったから」は理由にならない——
タスク管理機能は記録が作業者の裁量に依存し省略や消失に気づけないため、
正本にはしない）。

作業に取りかかる前に、まず以下を実行してディレクトリを作り（無ければ
作られる。既にあれば何もしない）、チェックリストファイルを作成する。

```bash
mkdir -p .verify-docs/dist
cat > .verify-docs/dist/$(date +%Y-%m-%d)-<作業内容の短い識別子>.md <<'EOF'
# 作業チェックリスト: <作業内容>

- [ ] 文書パス1
- [ ] 文書パス2
EOF
```

`<作業内容の短い識別子>`・`<作業内容>`・チェックボックスの中身は実際の
対象に置き換える。実行環境のタスク管理機能（`TaskCreate`/`TaskUpdate`
など）が使える場合は、進捗の可視化のために**併用してもよいが物理
ファイルの代わりにはできない**。**手段を問わず、置き場所は1つに保つ**
（会話中の複数メッセージに分けて書く、同じ作業のリストを複数ファイルに
分散させる、といったことはしない）。`.verify-docs/` は
[config.md「作業チェックリストの保管先」](../../verify-docs/references/config.md#作業チェックリストの保管先verify-docs)
の通り検査対象から除外されるため、**作業ログとして削除せず残してよい**。

## リストの運用

**リストの並び順は、確認する順番をそのまま表す。** 項目の並び替え・削除は
行わない——確認済みの項目もチェックを付けたまま残し、消さない。これにより
リストを見るだけで「何を・どの順で確認する予定か」と「どこまで終わったか」
の両方が常に分かる状態を保つ。

1件確認し終えるたびに、その項目にチェックを入れ（`- [ ]` → `- [x]`）、
**日時・担当・判断理由を書き添える**（`verify-docs.todo.json` の `reason`
欄・`allow-duplicate` マーカーの理由コメントと同じ考え方）。実行環境の
タスク管理機能を併用する場合、日時・担当（セッション ID など）は機能側の
記録に任せてよいが、判断理由（例:「重複なし」「X に統合しポインタ化」
「要人確認」）は物理ファイル側にも明記する。

記入例（3件中2件を確認済み、1件は未確認のまま次に控えている状態）:

```markdown
- [x] README.md — 2026-09-12 / session_xxxx / 重複なし
- [x] CONTRIBUTING.md — 2026-09-12 / session_xxxx / SKILL.md と重複 → ポインタ化して統合
- [ ] verify-docs/README.md
```

**この手順の判定は再現性を持たない（同じ入力でも見落としが起こりうる）。**
その見落としの一種である「確認したつもりで確認し忘れた項目」・
「チェックリストを作らずに検査だけ実行してしまう」の両方を機械的に
防ぐのがチェックリストの役目である。全項目にチェックが入るまで次の
判断段階には進まない。

### サイズを変更した場合の記録

分割・統合・ポインタ化によって文書のバイト数を変えた項目は、**圧縮前
サイズ・圧縮後サイズ・圧縮率を該当項目に記載する。** 圧縮率は
`(1 - 圧縮後 / 圧縮前) * 100` で計算し、小数第1位までとする。

```markdown
- [x] verify-docs/SKILL.md — 2026-09-12 / チェックリスト作成手順を
      references/checklist.md へ切り出し / 11,549B → 11,269B（2.4%減）
```

## 完了時に総評を書く

全項目にチェックが入った時点で、チェックリストファイルの末尾に
`## 総評` の見出しで以下を記載する（省略不可。項目が1件のみの場合も書く）。

- **検査したファイル数**（`node scripts/verify-docs.mjs` の出力にある
  「文書 N 件」の N、または意味的重複チェックの対象文書数）
- **検出した違反・重複の件数**（種別ごとの内訳。0件ならその旨明記）
- **効果**（是正によるバイト数の増減、統合した重複の件数、サイズ変更が
  無ければ「サイズ変更なし」と明記）

```markdown
## 総評

- 検査対象: 3ファイル（verify-docs.mjs出力）
- 検出した違反: 0件
- 効果: SKILL.md 2ファイルの合計サイズを 21,481B → 17,799B に削減
  （17.1%減）。チェックリスト作成手順を独立した参照文書に切り出した。
```
