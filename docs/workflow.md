# 推奨フロー

文書群を一巡して改善するときの、同梱スキルと追加の推敲スキルの実行順を扱う。

## 同梱スキルだけを使う場合

文書の構造を整え、文書間の重複を解消してから、文を簡潔にする。

1. 文書構造の検証・是正（`verify-docs`）
2. 文書間の意味的重複の解消（`dedupe-docs`）
3. 意味を変えない簡潔化（`tighten-docs`）
4. 文書構造の再検証

どのエージェントでも、次の共通依頼を使える。

> verify-docs、dedupe-docs、tighten-docsをこの順に実行し、完了後に文書構造を再検証して

既存文書の配置に拘らず、文書群を一つの正本体系へ再編するときは、2で
`dedupe-docs` の自律正本化モードを明示する。このモードは質問待ちで停止せず、内容統合、
新正本と必要な階層の作成、統合済み不要文書の削除まで行い、リスクを作業記録へ残す。

> verify-docs、dedupe-docsを自律正本化モードで実行し、完了後に文書構造を再検証して

同一の文書群に既定モードと自律モードを実行して選ぶ場合は、
[文書保守モードの比較](mode-comparison.md)に従い、圧縮率と必須事実台帳を比べる。

意味変更リスクよりも対象ファイルの圧縮完走を優先するときは、3で
`tighten-docs` の自律圧縮モードを明示する。このモードは質問待ちで停止せず、保護対象を
除いて対象内の候補を圧縮し、リスクを作業記録へ残す。

> verify-docs、dedupe-docs、tighten-docsを自律圧縮モードでこの順に実行し、完了後に文書構造を再検証して

## 日本語技術文書を推敲する場合

`japanese-tech-writing` が導入済みなら、`dedupe-docs` の後、`tighten-docs` の前に
実行する。重複を先に解消すれば、後で案内に置き換える文まで推敲せずに済む。

1. 文書構造の検証・是正（`verify-docs`）
2. 文書間の意味的重複の解消（`dedupe-docs`）
3. 日本語技術文書としての推敲（`japanese-tech-writing`）
4. 意味を変えない簡潔化（`tighten-docs`）
5. 文書構造の再検証

`japanese-tech-writing` は本パッケージに同梱しない。導入済みの環境では、次の共通依頼を使える。

> verify-docs、dedupe-docs、japanese-tech-writing、tighten-docsをこの順に実行し、完了後に文書構造を再検証して

## 再検証する位置

最初と最後の検証は、工程全体の入口と出口を確かめるために置く。`dedupe-docs` と
`tighten-docs` も、変更直後に自身の手順として再検証する。文書の移動、ポインタ化、
見出しの変更、節の削除でリンクや文書サイズの条件を壊していないことを、次の工程へ
進む前に確認するためである。
